最低业务验收：管理员创建 A、B 两用户；A 获两个模型，B 获一个；两人分别创建 key。B 不可调用第二个模型，不可查看/修改 A 的 key 和日志；key 限制不可扩大用户权限；停用 A 后其所有 key 的新请求失败。管理员调用 key 仍遵守自身配置限制。

迁移：备份数据库 → 新版本迁移 → 管理员明确认领旧 user_id=0 的 token → 校验 → 切换验证 → 删除不再需要的明文。保留可恢复的升级步骤，不将历史 token 默认为跨用户超级凭证。

## S3 凭据调度、限流与并发

功能实现与本地验收已完成，分支为 `feat/s3-admission`。本阶段覆盖以下七项；合并前仍须当前代码的完整 Linux CI 通过。首批准入提交 `11e9495` 的 [Verify #38710745232](https://github.com/ANRCM0/TXAPI/actions/runs/38710745232) 已通过；最终收口提交的 Verify 记录作为本阶段最终集成验收依据。

- [x] S3-01 每次尝试按已授权模型选择渠道，再选择可用凭据；支持凭据 CRUD。自定义 picker 仅选择池内凭据 ID，不能改写 Key、快照或重试排除项；并发删除仍保留末个凭据。
- [x] S3-02 优先级 + 加权选择；固定随机种子验证渠道和凭据分布、权重区间边界、主备回退。异常权重有运行期保护。
- [x] S3-03 按上游错误原因更新健康；有界指数冷却、连续失败拉黑、人工禁用/恢复、到期试探和后台恢复。观察到失败后同步发布运行期冷却，异步持久化事件从最新数据库状态串行计算；手工操作通过健康代次与写入前版本条件阻止旧事件覆盖。
- [x] S3-04 实例、用户、Key、渠道四级有界并发；取消、失败、总超时、panic 释放，重复释放不重复扣减；单个用户不能占满全部实例名额。
- [x] S3-05 用户跨 Key RPM 与 Key RPM/估算 TPM；窗口和跟踪容量有界。超限立即拒绝，当前无需等待队列；不淘汰有效限流窗口来放行新身份。TPM 采样不截断实际转发请求体。
- [x] S3-06 重试受总时长、配置次数与初始可用凭据数约束，不重用已试凭据；每次重新读取原授权模型的渠道候选。上游 401/403/408/429/5xx 可换凭据，客户端参数错误、客户端取消、响应已提交不误重试，不扩大用户授权。
- [x] S3-07 会话亲和通过 `server.session_affinity` 显式启用，默认关闭；可信 user_id 隔离会话，客户端头只使用摘要。凭据快照顺序变化不破坏缓存映射，环节点和缓存条数有上限；失效目标回退当前可用池且保留授权约束。尚无真实上游收益数据，部署前须测量缓存命中率、延迟或成本收益才启用。

验收：坏凭据不会因健康落库延迟而被后续请求持续选中；正常凭据按优先级和权重分流；客户端参数错误不惩罚凭据池；冷却到期可恢复；压力和取消后并发计数归零；跨 Key 不能绕过用户限制。权重分布按固定样本和统计容差验收，不要求少量样本精确 9:1。

2026-10-15 本地 Windows/amd64 验证包括构建、vet、全量普通测试和启动/迁移→鉴权→非流式/流式链路冒烟；Linux 全量 race、契约/依赖与冒烟由分支 Verify 承担。回归另覆盖并发健康事件、人工恢复/禁用与换 Key 的旧结果隔离、v2→v3 数据保留、幂等重启与旧版本拒绝打开新库。完整配置和升级/回滚说明见 [DEVELOPMENT.md](DEVELOPMENT.md#s3-并发准入与用户请求速率)。

边界：当前限额是单进程级，超限立即拒绝，选中渠道满时不另找渠道；没有分布式配额、等待队列、用户 TPM 跨 Key 聚合或严格账本。健康持久化队列有界，满时告警丢弃持久化事件，但运行期冷却仍立即生效；进程崩溃不能保证未持久化的健康状态被恢复。以上不宣称 S4/S5 已交付。

## 每个阶段的交付约定

1. 先写清变更影响和可复现问题，再实现最小变更。
2. 按 [开发与验证节奏](DEVELOPMENT.md#开发与验证节奏) 分可独立验收的功能批次推进：批量开发、集中验证、集中修复、再合并，不等整个阶段结束才测试。新行为有与风险对应的回归；批次内按需编译和关键风险定向测试，批次稳定后集中检查，最终完整 CI 通过。同一代码已有有效证据时不无理由重复全量测试或细碎推送。
3. 不提交真实密钥、数据库、编译产物、日志、临时分析或个人配置。
4. 对性能敏感路径附基准对照；纯说明文档修改只检查差异、链接与一致性，不新增单元测试或手动重复全量测试/CI；脚本、契约和运行配置变更按实际影响验证。
5. 数据库变更附迁移和回滚限制；删除实现前确认调用方已迁移。
6. 完成后更新本文件勾选项和 README 能力状态，避免“文档完成等于功能完成”。

下一项工作：S3 最终 CI 通过后审查合并，再按团队边界推进 S4 管理界面、配置发布与交付。协议团队可基于稳定的 F0/S3 接口独立扩展。部署 S2 前仍须备份数据库并显式认领旧无主 Key；合并代码不等于已迁移实际运行数据库。
